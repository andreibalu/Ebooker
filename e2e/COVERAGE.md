# Unpaged flow coverage

The native suite drives the actual SwiftUI app with tester-army/e2e's mobile engine. Every deterministic case uses a DEBUG-only separate persistent SwiftData store, two books with real generated PCM audio, two saved categorized moments, one reading session, and the verified Pride and Prejudice catalog row (LibriVox ID 253). Relaunch assertions omit the reset flag. These fixtures do **not** prove the system Files picker, App Store (sandbox or production) transactions, CloudKit transport, or Apple Intelligence generation. Local StoreKit purchases, the PhotosPicker, permission prompts and a localhost fake of the LibriVox feed are exercised by the group 2 suites below.

## Isolation and safety

Use only the dedicated `Unpaged e2e` simulator. `-e2e-reset-fixture` removes only `Application Support/E2EFixtures`, including its fixture-specific `DownloadJobs` journal before coordinator restoration; audio fixture writes use fixed `E2E-Listening-Book` and `E2E-Another-Book` folders. `-e2e-import` replaces only the picker input with a real generated WAV and then executes the production metadata-review and import pipeline. It does not qualify the system Files picker. The fixture never deletes production databases, changes account credentials, or overrides paid entitlements. DEBUG-only `-e2e-online` allows real reachability for the explicit live suite; fixture mode bypasses automatic full catalog synchronization. `purchases.e2e.ts` buys the trial and the coffee tip only against the local `Products.storekit` configuration and clears storekitd's ledger before and after each test; no App Store account is involved. ABS validation uses only malformed dummy input. `onboarding.e2e.ts` resets and grants microphone/speech TCC for the app on the dedicated simulator only.

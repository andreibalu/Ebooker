# Slice 7: Android Auto and system integration

## Implementation

`PlaybackService` is now a Media3 `MediaLibraryService` with one ExoPlayer.
The phone, system controllers and car clients share `PlayerController`. Browser
selection uses its existing resume policy, saved position, progress penalty,
reading recorder and per-book EQ setup. The manifest declares both the Media3
library service and legacy media browser action, plus the Android Auto media
application descriptor. No microphone permission, purchase UI or backend was added.

The root has Favorites, Library and Shelves in CarPlay order. Favorites and
Library use the Library sort preference, as `CarPlayCoordinator` does. A row with a saved progress marker
shows that marker's track and clock position; other rows show the author.
Shelves recommends locally cached curated classics not already in the library,
in curated ID order, matching CarPlay's recommendation exclusion.
There is no car download action. Selecting a classic reuses its catalog identity,
including a downloaded row, or adds streaming tracks through
`CatalogLibraryService`. Android currently has no archived-book representation.
This slice does not add a schema or an archive mechanism. The existing streaming
identity check now locks across service instances to prevent simultaneous additions
from creating duplicate rows.

Both `onGetSession` and `onGetLibraryRoot` check callers. The application,
Android-trusted media controllers, Android Auto's
`com.google.android.projection.gearhead` and Automotive's `com.android.car.media`
are allowed. Media3 validates controller package/UID identity. The E2E package
allowance lives in a separate debug source set; the release implementation returns
false. The generated-artwork provider applies the same policy, verifies read-only
single-book paths and exposes only PNG covers. It cannot open audiobook files.

Browse artwork uses local content URIs, generated by the existing
`GeneratedArtwork`. Root icons use local Material vector resources. Playing
metadata retains the existing PNG and adds its content URI. This follows
[Android's car artwork requirements](https://developer.android.com/training/cars/media/create-media-browser/media-artwork),
which require local URIs for Automotive and warn against many inline bitmaps in
browser results. Artwork cache files live in the app's cache directory.

Now playing exposes Playback Rate, Save Moment, Mark Progress and Chapters as
Media3 custom commands with Material icons. Rate cycling uses the existing
supported rates. Save delegates to the phone's manual draft, including the
configured offset, then labels it `CarPlay N`, matching iOS's global sequence
and wrap after 999. Mark delegates to the phone's explicit progress marker.
Chapters returns the `chapters` browse parent; compatible MediaBrowser clients
can fetch its numbered chapter IDs and play a row. Whether a real head unit
presents that navigation from a custom command remains unverified.

Search uses case/diacritic-insensitive title or author containment. Matching
library rows precede cached curated classics; duplicate titles are omitted and
results cap at thirty. An empty query picks the most recently played playable
library row. MediaSession set/add/search and playback-resumption requests resolve
app-owned IDs rather than accepting arbitrary controller URIs. Streaming selection
without connectivity reports `No internet connection` through Media3's session
error and a network playback error.

The static launcher shortcut is `Play Latest Book`. It and
`android.media.action.MEDIA_PLAY_FROM_SEARCH` use the same search/resolution
rules. The activity consumes the action before asynchronous lookup and does not
replay it on rotation or ordinary relaunch. `singleTop` supports a new request
while the activity is already open. Android supplies speech recognition.

## Dependencies and schema

No runtime dependency was added. The separate E2E driver adds the existing exact
`androidx.media3:media3-session:1.8.0` pin to connect a real MediaBrowser from its
own process. The app remains one production module. User SQLite remains v4.

## Remaining qualification

Android Auto, Automotive OS and Desktop Head Unit are unavailable. Their actual
browse/now-playing rendering, custom button placement, chapter navigation and
speech recognition are unverified. Emulator checks cannot qualify physical phone
audio, Bluetooth/headset controls, car connection lifecycle or background power
behavior. Live LibriVox streaming and real ABS/VPN access are not established by
cached metadata, host tests or fake-server tests. Android fonts, native icons and
host-controlled car layouts differ from SwiftUI/CarPlay. This slice makes no
pixel-identical car UI claim.

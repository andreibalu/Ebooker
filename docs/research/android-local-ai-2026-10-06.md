# Android local AI for Unpaged

**Research date:** 2026-10-06
**Scope:** on-device smart moment naming and recaps, with optional offline transcription of local audiobook segments. Planning only; no Android implementation or device benchmarking.

## Recommendation

Treat Android AI as an optional local capability with two independent stages: transcribe a playable local audio segment, then transform its transcript into the Unpaged moment/recap fields. Keep manual bookmarks and playback fully usable when either stage is unavailable. Never fall back to a cloud transcription or generation service; if local processing is unavailable, explain that the AI action cannot run and keep the user's manual path.

For an initial feasibility spike, compare (1) ML Kit GenAI Prompt API with system Gemini Nano on devices where that exact API reports ready, and (2) an explicitly downloaded LiteRT-LM text model. Use Qwen3-0.6B dynamic INT4 as the smallest concrete LiteRT candidate, with Gemma 3 1B INT4 QAT as a quality/size comparison. For local file transcription, prototype `whisper.cpp` with multilingual tiny and base checkpoints. This is a test shortlist, not a shipping model decision: no Unpaged prompt-quality, Romanian audiobook, latency, thermal, battery, or target-phone tests have been run.

Do not hard-code an Android version, brand, RAM value, chipset, or “AI phone” label as proof of capability. Query each system API at runtime and verify a downloaded model can initialize on that device. Google publishes exact device support for its Gemini Nano APIs; the open-model runtimes publish examples, not a complete certified handset list or universal minimum-RAM threshold.

## Workload mapped from the iOS reference

The current iOS smart-save path transcribes a 90-second window around the playhead (75 seconds behind and 15 ahead). Its model produces a 3–5-word title, one to three categories, mood, up to six character names, an optional exact transcript quote, and a two-sentence note capped at 40 words. The recap path transcribes the previous 200 seconds and generates a two-sentence recap, optionally with a three-to-four-word progress headline. Both use local model generation. The current recap implementation requires downloaded audio; streaming-only audio has no local segment file. These are behavior references, not Android implementation instructions. See `Pageless/ViewModels/PlayerViewModel.swift`, `Pageless/Services/MomentNamingService.swift`, `Pageless/ViewModels/AudiobookDetailViewModel.swift`, and `Pageless/Services/RecapService.swift`.

The small prose output makes local text generation plausible. Transcription is the harder timing and compatibility problem. ML Kit Speech Recognition's file-descriptor path accepts only raw, headerless, mono, 16-bit PCM at 16 kHz and requires input at real-time pace; it does not support reading an ordinary file at full speed. A just-in-time 90-second or 200-second request therefore cannot be fed faster than its audio duration through this route. The API could be evaluated as a continuously fed foreground pipeline, but foreground, file-conversion, interruption and battery behavior remain untested. `whisper.cpp` can process local audio files directly and is the better first route to benchmark for post-pause segment actions.

Keep transcript-derived quotes strictly verbatim: ASR can make recognition errors, and text generation can invent a plausible quotation. Only save a quote if it exactly matches a transcript sentence after controlled normalization; otherwise omit it. The current iOS implementation already follows this principle.

## Built-in system model: Gemini Nano through AICore / ML Kit

Gemini Nano is supplied and managed by Android's AICore system service. ML Kit GenAI calls run locally; once the device and model are ready, inference does not send prompts to an app server. AICore is shared across apps, so the app does not bundle duplicate weights. Initial setup/configuration and model downloads may need internet. AICore routes those downloads through Private Compute Services, not through app inference. See [Android Gemini Nano and AICore](https://developer.android.com/ai/gemini-nano), [ML Kit GenAI overview](https://developers.google.com/ml-kit/genai), and [Prompt API setup](https://developers.google.com/ml-kit/genai/prompt/android/get-started).

The custom Prompt API is the best system route for Unpaged's structured text transformation because the feature-specific Summarization API is constrained to one to three bullets. Prompt API accepts custom text prompts and structured output, but is **beta**, has no SLA or deprecation protection, requires Android API 26+, limits input to under 4,000 tokens (about 3,000 English words), and asks apps to avoid outputs over 4,000 tokens. AICore may return per-app busy/battery quotas; inference is allowed only while the app is the top foreground app. An unlocked bootloader is unsupported. Check `AVAILABLE`, `DOWNLOADABLE`, `DOWNLOADING`, and `UNAVAILABLE` every time before exposing the action; downloads and setup may fail or be delayed.

ML Kit Speech Recognition is **alpha**, also with no SLA. Basic mode uses a traditional on-device recognizer and is generally available on most Android API 31+ devices; Advanced Gemini Nano mode is currently listed for Pixel 10 and Pixel 11 devices. API integration has a lower API 26 minimum, but that does not make Basic mode available on API 26–30. Google's published Basic locale list includes English, French, Italian, German, Spanish, Hindi, Japanese, Brazilian Portuguese, Turkish, Polish, Chinese, Korean, Russian, and Vietnamese; Advanced lists additional languages, but Romanian is not in the published high-accuracy locale list. The docs note other locales may exist and ask developers to evaluate actual use cases. Check status and language availability at runtime; do not promise Romanian support based on API level or device family.

The LiteRT Qwen examples show why file size alone is not enough for a RAM policy. A 474.61 MiB 2K mixed-INT4 artifact measured a 585 MB peak private footprint on one recent Samsung device's GPU, but roughly 1.8 GB on listed vivo/TECNO GPUs and 2.9 GB on CPU for Samsung/TECNO. The separate 586 MB 4K INT8 artifact showed 2.7–4.3 GB peak private footprint on the sampled devices/backends. These are command-line, vendor-reported measurements and vary by SKU, OS, thermal state, backend, quantization, runtime and prompt shape. They are evidence of variance, not guarantees. A 4–6 GB physical-RAM threshold cannot be responsibly inferred from these sparse data; Android process pressure and concurrent playback also matter.

## Capability policy and validation gates

1. **Separate concerns:** `SegmentTranscriber` and `Moment/RecapGenerator` interfaces, with a capability/status provider. A system model and an app-downloaded model are different sources with separate readiness states.
2. **Check at point of use:** For ML Kit, query status and language, handle download progress/failure and API quotas, and honor the foreground-only rule. Never show a feature as ready solely because a device name is on Google's list.
3. **Make downloads explicit:** For open weights, show model name, approximate download size, license link, required free space, progress, cancel/retry and delete controls. Verify the downloaded artifact before loading. Keep models optional and store them outside app-install assets so an update does not silently redownload gigabytes.
4. **Fail locally:** If the system feature is unavailable, a download is declined/failed, RAM is insufficient, a model crashes, or ASR language support is absent, retain a manual bookmark and show a short unavailable message. No network request should contain audio, transcript, prompt or generated recap. Add a test that observes no AI network fallback path.
5. **Benchmark before promises:** Use real retail devices: at least one supported Pixel for Prompt/Advanced Speech, one supported non-Pixel Prompt device, and lower-memory mid-range ARM64 devices for downloaded weights. Measure cold/warm first-token time, ASR real-time factor on 90s and 200s excerpts, peak app/process memory while playback is active, battery/thermal behavior, cancellation/background, storage/download recovery, and English/Romanian word error plus moment/recap quality. Include offline first launch and AICore-unavailable cases. Neither vendor benchmarks nor simulator runs establish Unpaged compatibility.

**Planning implication:** Gemini Nano is the lowest app-storage path on officially supported phones, but exact Prompt API coverage is narrower than Google's feature-specific support and its APIs are beta/alpha. A downloaded LiteRT model and `whisper.cpp` can broaden local processing beyond that list, but no minimum-RAM phone class or latency promise is verified. Keep both model availability and AI itself optional, preserve manual use, and make a no-cloud policy an invariant.
